# 下載與媒體庫

nPlyr 可以把串流播放清單儲存為真實檔案，並讓你在下載完成前就開始觀看。你的歷程、書籤與下載內容都收錄在媒體庫中。

## 下載 HLS 播放清單

當你將一個 `m3u8` 傳送給下載器時，nPlyr 會：

1. 取得主播放清單與子播放清單（驗證 HTTP 狀態，並確認回傳體是真正的 `#EXTM3U` 文件）。
2. 下載每一個片段，拒絕空白或格式錯誤的片段行，從而讓 404 錯誤頁永遠不會被誤當成播放清單。
3. 將片段重新封裝進 **MP4** 容器。

### 磁碟配置

- 下載中：`<name>.temp/`
- 完成後：重新命名為 `<name>/`，影片位於 `<name>/<name>.mp4`。
- 如果重新封裝失敗，原始的 `.ts` 會被保留並標記為 `completed`（而非 `failed`），以免資料遺失；單一片段失敗則標記為 `.failed`。
- 續傳依據標記檔案與清單工作——你可以暫停並繼續。

> 由[嗅探器](/zh-TW/guide/browser)擷取的任何自訂請求**標頭**（referer、cookie、auth）都會被保留，並隨每個請求一併傳送。nPlyr 絕不偽造 referer 或 origin——只會在需要時補充 user-agent。

## 邊下邊播

開啟此功能可**邊下載邊觀看**。nPlyr 透過一個本機回送伺服器提供已部分下載的檔案，並領先於下載前沿開始播放（`progressiveLookahead = 20` 個片段）。它**預設關閉**。

邊下邊播生效時：

- 播放清單的金鑰（`#EXT-X-KEY`）行在交付前會被剝離，
- 播放器始終引用**原始**來源 URL（本機伺服器是透明的），
- 如果某個網域失敗，該網域會在本次工作階段中被列入黑名單，部分檔案會被取消並刪除，且 nPlyr 不會靜默改道。

邊下邊播與去廣告互斥；只有在未使用邊下邊播時，去廣告才會接管。

## 多清晰度與字幕

- **清晰度**選擇作用於**下載**（下載前挑選變體；若不挑選，nPlyr 會短暫等待選擇，否則回退到最佳變體）。
- **字幕**會隨媒體一起下載，並儲存為片段暫存目錄中的 `subtitle.<ext>`，從而始終與檔案綁定。

## 媒體庫

媒體庫在一個可搜尋的位置匯集三樣東西：

- **歷程**——你看過什麼、何時看過。
- **書籤**——你儲存的來源與項目。
- **下載**——透過下載器儲存的檔案。

所有內容都可透過標題搜尋，並且媒體庫設計為在登入同一環境的 Mac 與 iPhone 之間同步。

## 去廣告

nPlyr 使用與 Chrome 擴充功能攔截清單相同的**訂閱規則**格式（即 hikerView 採用的方式）來封鎖廣告。你訂閱一個過濾清單，nPlyr 便會在瀏覽器中以及播放期間過濾請求。這與邊下邊播相互獨立——兩者同一時間只有一個生效。
