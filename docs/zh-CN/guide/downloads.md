# 下载与媒体库

nPlyr 可以把流式播放列表保存为真实文件，并让你在下载完成前就开始观看。你的历史、书签与下载内容都收录在媒体库中。

## 下载 HLS 播放列表

当你把一个 `m3u8` 发送给下载器时，nPlyr 会：

1. 获取主播放列表与子播放列表（校验 HTTP 状态，并确认返回体是真正的 `#EXTM3U` 文档）。
2. 下载每一个分片，拒绝空白或格式错误的分片行，从而让 404 错误页永远不会被误当成播放列表。
3. 将分片重封装进 **MP4** 容器。

### 磁盘布局

- 下载中：`<name>.temp/`
- 完成后：重命名为 `<name>/`，影片位于 `<name>/<name>.mp4`。
- 如果重封装失败，原始的 `.ts` 会被保留并标记为 `completed`（而非 `failed`），以免数据丢失；单个分片失败则标记为 `.failed`。
- 续传依据标记文件与清单工作——你可以暂停并继续。

> 由[嗅探器](/zh-CN/guide/browser)捕获的任何自定义请求**头**（referer、cookie、auth）都会被保留，并随每个请求一并发送。nPlyr 绝不伪造 referer 或 origin——只会在需要时补充 user-agent。

## 边下边播

开启此功能可**边下载边观看**。nPlyr 通过一个本地环回服务器提供已部分下载的文件，并领先于下载前沿开始播放（`progressiveLookahead = 20` 个分片）。它**默认关闭**。

边下边播生效时：

- 播放列表的密钥（`#EXT-X-KEY`）行在交付前会被剥离，
- 播放器始终引用**原始**源 URL（本地服务器是透明的），
- 如果某个域名失败，该域名会在本次会话中被拉黑，部分文件会被取消并删除，且 nPlyr 不会静默改道。

边下边播与去广告互斥；只有在未使用边下边播时，去广告才会接管。

## 多清晰度与字幕

- **清晰度**选择作用于**下载**（下载前挑选变体；若不挑选，nPlyr 会短暂等待选择，否则回退到最佳变体）。
- **字幕**会随媒体一起下载，并保存为分片临时目录中的 `subtitle.<ext>`，从而始终与文件绑定。

## 媒体库

媒体库在一个可搜索的位置汇集三样东西：

- **历史**——你看过什么、何时看过。
- **书签**——你保存的源与条目。
- **下载**——通过下载器保存的文件。

所有内容都可通过标题搜索，并且媒体库设计为在登录同一环境的 Mac 与 iPhone 之间同步。

## 去广告

nPlyr 使用与 Chrome 扩展拦截列表相同的**订阅规则**格式（即 hikerView 采用的方式）来屏蔽广告。你订阅一个过滤列表，nPlyr 便会在浏览器中以及播放期间过滤请求。这与边下边播相互独立——两者同一时间只有一个生效。
