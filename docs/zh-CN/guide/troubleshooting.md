# 故障排查

本页汇总 nPlyr 在 macOS 与 iOS 上的常见问题及解决方法。

## 应用无法启动或启动即崩溃

1. 确认你的系统满足最低要求（macOS 14 Sonoma 及以上，或 iOS / iPadOS 16 及以上）。
2. 退出并重新启动应用。
3. 如果你侧载了开发版本，请确认描述文件仍然有效。

## 视频无法播放（一直转圈或报错）

- 确认链接是一个**直链**媒体 URL（`mp4`、`m3u8`、`flv`、`ts` 等），而不是一个页面。使用[浏览器与嗅探器](/zh-CN/guide/browser)抓取真正的链接。
- 某些站点需要特定的**请求头**（referer、cookie、auth）。通过嗅探器抓取链接会自动保留这些请求头。
- `TS → MP4` 透传需要格式提示；如果某个 TS 源失败，请尝试从线路切换器选择另一条线路。
- 来自源的 `403` 通常是短暂的站点侧限流；请等待后重试，而不是盲目更改请求头。

## 嗅探器在某个网站上什么也抓不到

- 该页面可能通过专有播放器或 DRM 加载视频，从不请求普通媒体文件。此时，与该源 API 通信的[小程序](/zh-CN/guide/miniapps)才是正确的工具。
- 尝试重新加载页面，或在[设置](/zh-CN/guide/settings)中将**浏览器 user-agent**切换到移动端 / 桌面端。

## 某个键盘快捷键不起作用

- 快捷键仅按修饰键匹配（`⌘`、`⌥`、`⌃`、`⇧`）；方向键与小键盘不属于绑定的一部分。
- 当你在文本框（URL 栏、搜索框）中输入时，单键快捷键会被有意抑制，以免与你的输入冲突。
- 如果某个绑定依然感觉失效，请检查它是否在**系统设置 → 键盘 → 键盘快捷键**中被系统或应用快捷键遮蔽。

## 下载停滞或失败

- 单个分片失败会将下载标记为 `.failed`；可从标记文件续传。
- 如果某个域名反复返回 `404`，nPlyr 会在本次会话中将其拉黑，且不会静默改道——请选择另一个源。
- 重封装失败会保留原始 `.ts` 并标记为 `completed`，因此你的数据不会丢失。

## 某个小程序的行为与 Android 上不同

原始引擎是 Android/Java（Rhino）。nPlyr 在 JavaScriptCore 上运行规则，并为规则所依赖的部分实现了一个 **Rhino→Java 兼容层**。部分 Java 特有的行为是有意不支持的。请查阅[兼容性](/zh-CN/guide/miniapp-compatibility)页面；如果某条具体规则失败，请报告规则名称。

## 重置 nPlyr

你可以从**设置 → 高级 → 重置**重置应用的本地数据（媒体库、书签、小程序变量）。这不会影响你已购买的解锁。
